# PureLand

PureLand is an open method for asking whether an information practice makes attention more sovereign without making people easier to extract from.

I have watched my own attention become inventory. I have reached for the feed because I was restless, stayed because I was angry, and called the accumulation research because that sounded better than greed. I have also used the same information ecosystems to learn, make films, find people I love, and build this kit. I am not outside the system I am trying to see.

## Working hypothesis

We reclaim sovereignty through attention by noticing how the three poisons and five hindrances appear in ordinary life, then adapting with skillful means. Greed and generosity make the design problem concrete. An open fork can reproduce extraction through reach, status, data capture, and unpaid contribution. It can also return methods, credit, learning, and agency to the people who make it useful.

This is a PureLand synthesis. It is informed by Buddhist teachings, but it is not a claim that those teachings are a technical taxonomy or that every information system maps cleanly onto them. See [PRACTICE-FRAME.md](PRACTICE-FRAME.md) and [PROVENANCE.md](PROVENANCE.md).

## The method

PureLand has three layers:

1. **Contemplative diagnosis.** Notice the mental condition shaping contact. Do not turn a Buddhist category into a label for someone else.
2. **Observable practice.** Trace access, consent, attribution, value, attention, and return using records another person can inspect.
3. **Bounded adaptation.** Change one condition, name who bears the cost, and test whether the change increases agency without increasing extractability.

The scorecard does not produce a certification. The extraction check does not produce a moral verdict. The contemplative frame does not diagnose people. Each instrument should expose a decision that can be challenged.

## Status: version 0.1

This is a research prototype. It has not been validated. No independent field results are claimed. The [field-trial ledger](FIELD-TRIALS.md) is intentionally empty until contributors submit inspectable evidence.

The next research gate is five to ten independent applications across more than one kind of practice, with two readers where possible. Disagreement stays in the record. See [FIELD-TESTING.md](FIELD-TESTING.md).

## Use it and return something

Fork the repository. Apply one instrument to a practice you know. Record where it fails. Return a field report, issue, pull request, or documented disagreement. A fork is useful when learning travels back, not merely when code travels out.
