# Security and confidential reports

Do not place participant material, credentials, direct or indirect identifying data, client or confidential records, protected community knowledge, consent records, or a private vulnerability in a public issue.

Use GitHub's private vulnerability reporting route when the repository displays it under **Security → Report a vulnerability**. If that route is unavailable, open a public issue containing only a request for a private contact channel. Do not describe the sensitive content.

The repository does not designate another private contact route by default. The maintainer must establish an appropriate private channel before asking for or receiving protected details. If no appropriate channel is available, pause the report. Do not treat delay, silence, or inability to establish a channel as permission to disclose the material publicly.

For an exposed secret, rotate or revoke the secret before reporting it. For exposed participant material, stop distribution where controlled, preserve a minimal private incident record, notify the affected rights holder through an appropriate channel, and follow the withdrawal limits in [RIGHTS-AND-CONSENT.md](RIGHTS-AND-CONSENT.md).

For a protected correction or takedown request, record the requested change, the affected artifact, the rights basis, the action taken, the action date, and any copies or uses the project cannot control. Do not place that record in the public repository. A public resolution may state the outcome only when doing so does not create new exposure.

This repository contains methods, templates, and completed field-test records whose every value is public-safe. It should never contain live participant data.
