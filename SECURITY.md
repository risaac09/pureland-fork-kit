# Security and confidential reports

Do not place participant material, credentials, identifying or indirectly identifying information, confidential records, protected community knowledge, or a private vulnerability in a public issue.

## Vulnerabilities

Use GitHub's private vulnerability reporting route when the repository displays it under **Security → Report a vulnerability**. If that route is unavailable, open a public issue containing only a request for a private contact channel. Do not describe the vulnerability or include sensitive content.

For an exposed secret, rotate or revoke the secret before reporting it.

## Rights, consent, correction, and takedown

For exposed participant material, stop distribution where the project has control, preserve a minimal incident record, and notify the affected rights holder through an authorized route. Follow the withdrawal limits in [RIGHTS-AND-CONSENT.md](RIGHTS-AND-CONSENT.md).

An affected person may request correction or takedown of a record the project controls. If the request requires protected detail, open a public issue that asks the maintainer to establish a private review channel and says nothing about the underlying material. Stage 2 starts only after that channel exists and the maintainer confirms the rights basis. This file does not designate an email address or private system.

Record the request, decision owner, actions, dates, review date, and any copies or uses the project cannot control. Do not promise removal from public archives, external backups, model weights, or downstream adaptations.

This repository may contain only methods, templates, and field-test records whose values pass a documented public-safe review. It should never contain live participant data or completed consent registers.
